------------------------------------------------------------
RESULTS CSV COLUMN EXPLANATION:
1. `task_id`        : Unique identifier of the benchmark task (e.g., easy_01, med_01, hard_01).
2. `tier`           : Difficulty tier based on primitive composition count (easy=1, medium=2, hard=3).
3. `method`         : Synthesis method name (BFS, A*, Weighted A* (w=2.0), Q-Learning RL).
4. `train_solved`   : True if the algorithm discovered a program satisfying all training pairs.
5. `test_solved`    : True if the discovered program correctly transformed the held-out test input.
6. `program_length` : Number of DSL primitive operations in the synthesized sequence.
7. `nodes_expanded` : Count of search states expanded from the queue (or steps taken by RL).
8. `time_ms`        : Wall-clock synthesis time in milliseconds.
9. `program`        : Exact sequence of synthesized DSL primitives (e.g. crop_to_content -> rotate_90 -> recolor(1->3)).

RECOMMENDED FACULTY DEMO ORDER (5-10 MINUTE FLOW)
============================================================

Follow this exact sequence during a live faculty demonstration:

STEP 1: PROJECT OVERVIEW (1 minute)
  Command: Get-ChildItem
  Talking points:
  - ARCSynth is a pure Python 3 + NumPy program synthesis engine.
  - Core search requires no neural network; optional DQN needs PyTorch. No network calls are made.
  - Formulates program synthesis as heuristic search over multi-pair state spaces.
  - Show modular code organization: objects -> grids -> dsl -> search/rl -> benchmark/evaluate.

STEP 2: RUN THE LIVE DEMO (2 minutes)
  Command: python demo.py
  Talking points:
  - Walk through the terminal output:
    1. Show the training pairs (Pair 1 and Pair 2) for benchmark task `hard_01`.
    2. Explain that the search algorithm simultaneously tracks all training pairs.
    3. Point out the selected algorithm: A* Search with the Pose-and-Paint heuristic.
    4. Highlight the synthesized program: `crop_to_content -> rotate_90 -> recolor(1->3)`.
    5. Show the step-by-step intermediate grids as the program is replayed on the test input.
    6. Emphasize that the held-out test output is an EXACT 100% match (zero pixel errors).
    7. Point out the speed: synthesizes in ~1.5 ms with only 4 nodes expanded!

STEP 3: EXPLAIN THE DSL AND SEARCH STRATEGY (1 minute)
  Command: python demo.py --list
  Talking points:
  - Explain the Domain-Specific Language (DSL) in `dsl.py`: 17 pure primitives.
  - Action space pruning: actions are dynamically constructed by inspecting training pairs
    (e.g., only viable recolorings or tile sizes are included), drastically cutting branching factor.
  - Contrast with exhaustive brute-force: A* uses heuristic guidance to find the goal with
    minimal expansions.

STEP 4: RUN FULL BENCHMARK EVALUATION (2 minutes)
  Command: python evaluate.py
  Talking points:
  - Evaluates 24 synthetic tasks across 3 tiers (Easy, Medium, Hard) against 4 algorithms:
    BFS, A*, Weighted A*, and Tabular Q-Learning.
  - Highlight the summary table at the end of the run:
    * BFS: 24/24 (100%) test solve rate, average 9.4 nodes.
    * A*: 24/24 (100%) test solve rate, average 5.5 nodes (expands ~half the nodes of BFS on hard tasks).
    * Weighted A*: 24/24 (100%) test solve rate, fastest execution time (~1.05 ms).
    * Q-Learning RL: 16/24 (66.7%) test solve rate in single-pass rollout without a search tree.

STEP 5: SHOW THE ALGORITHM COMPARISON IN RESULTS (1 minute)
  Command:
  Import-Csv results.csv | Where-Object { $_.tier -eq 'hard' -and ($_.method -eq 'BFS' -or $_.method -eq 'A*') } | Select-Object task_id, method, nodes_expanded, time_ms, program | Format-Table -AutoSize
  Talking points:
  - Point directly to `hard_01`, `hard_06`, and `hard_08`:
    * `hard_01`: BFS expanded 27 nodes; A* expanded only 4 nodes!
    * `hard_06`: BFS expanded 37 nodes; A* expanded only 4 nodes!
    * `hard_08`: BFS expanded 35 nodes; A* expanded only 4 nodes!
  - This proves the theoretical advantage of heuristic-guided search over uninformed search.

STEP 6: RUN THE COMPLETE TEST SUITE (1 minute)
  Command: python -m unittest discover
  Talking points:
  - 27 unit tests validating every module: object labeling, grid hashing, DSL primitives,
    benchmark generator, search algorithms, RL agent, and evaluation pipeline.
  - Runs in ~1 second with 100% pass rate, ensuring high code reliability and reproducibility.

STEP 7: MODULE RESPONSIBILITY SUMMARY (1 minute)
  Briefly summarize what each major file contributes:
  - `objects.py`         : 4-connectivity connected-component analysis and object extraction.
  - `grids.py`           : Grid hashing, ARC palette color maps, synthetic generation, serialization.
  - `dsl.py`             : 17 pure grid transformation primitives and dynamic action space builder.
  - `benchmark.py`       : Synthetic benchmark generator creating 24 non-trivial ARC-like tasks.
  - `search_bfs.py`      : Exhaustive depth-limited search for provably shortest programs.
  - `search_astar.py`    : Heuristic-guided priority search minimizing node expansions.
  - `search_weighted.py` : Weighted A* (w=2.0) for accelerated goal discovery.
  - `rl_agent.py`        : Tabular Q-learning agent for single-pass synthesis via feature vectors.
  - `evaluate.py`        : Rigorous multi-algorithm evaluation harness generating results.csv.
  - `demo.py`            : Clean, interactive CLI presentation layer for faculty demonstration.
